## What is implemented

The simulation decision/execution/evidence loop is a separate technical MVP. The local workspace supports field/season observations, human review, snapshots, inspections, measurements, resource planning, lot allocations, explicit case/cost links and a separate produce/order/receipt ledger. It binds to loopback and uses an outer combined handler to add routes, host checks, branding and Help. It does not run the simulation policy on actual equipment.

Resource/market histories are append-only and hashed, with source/context checks and guarded arithmetic. Legacy core records use their own correction paths. Test recordings cannot be confirmed into farm observations. Help examples are fictional; exports and downloaded captures are not rewritten with live UI content.

## Architecture and data notes

No destructive schema migration is needed for this batch. Existing payloads, source labels, quantities, core records and frozen bundles are preserved. New request checks apply through the combined Operations launcher; lower-level legacy launchers are not represented as hardened public entry points. Read validation ignores current-clock comparisons for previously saved event times so a historical record is not reclassified merely because the clock moved.

Paged lists still compute full ledger consistency and overview calculations, and reference metadata remains scoped but potentially large. Pagination is not a claim of large-scale database performance. Route composition, data-directory configuration, migration governance and query profiling remain independent planned work.
