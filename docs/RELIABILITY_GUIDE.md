# Saving, refreshing and troubleshooting

These changes apply when NEXUS starts through `python -m nexus.farm_app.operations`. The app remains a single-user local workspace. Origin checks are not account authentication and do not make it suitable for public hosting.

## Save a record safely

1. Choose the field and correct Actual/Test source before typing facts.
2. Enter supported values. Help examples remain fictional and never fill a form.
3. Save once. The form locks during the request to prevent a second edit being discarded while saving.
4. After success, inspect the saved record. If a timeout or response error occurs, inspect saved records before retrying; a lost response does not necessarily mean the server failed to save.
5. Use Revise current version with a reason for a correction. Do not create a second actual movement just to correct a transcription mistake.

Changing field/source, clearing the form or opening another record asks before discarding unsaved form values. Browser leave-page prompts vary by browser and may require prior interaction. Nothing is auto-saved. Dirty-state tracking stays in memory; it does not store form text in browser storage.

## Refresh and references

Refreshing resource/market records preserves selected references if they are still permitted in the current field/source view. If a selected record is no longer available, recheck it before saving. A newer selected view takes precedence over an earlier refresh response. Overview calculations remain scoped to field/source, not to the literal-text filter.

Use Previous records / Next records for the saved-entry list. Pages default to 100 records; API pages are capped at 200. Count labels identify the matching total. CSV, JSON and HTML exports still contain the complete filtered selection up to the existing 10,000-entry export limit, rather than silently exporting only the displayed page.

## Compact Help Centre

The index shows workflow summaries. Select a guide for complete field meanings, examples and save effects. Search and individual guides work without JavaScript. For a printable/offline copy, use the individual guide's download link. In-page panels still require JavaScript.

## Request errors

| Message / status | Meaning and next step |
| --- | --- |
| Same-origin request required · 403 | Use the page served by the same local host and port. Do not disable origin protection. A custom API client must deliberately send the matching Origin header. |
| Content-Type / encoding · 415 | JSON endpoints expect `application/json` in UTF-8. The existing audio endpoint expects `audio/wav`. Compressed request bodies are unsupported. |
| Duplicate JSON field · 400 | A custom client sent the same key twice, possibly nested. Correct the client; the server does not choose one value silently. |
| Nonfinite / deeply nested JSON · 400 | Send ordinary finite numbers and bounded structure. Unknown values belong in the workflow's supported blank/Unknown representation. |
| Content-Length / framing · 400 | Send one valid positive Content-Length. Chunked Transfer-Encoding and duplicate framing headers are unsupported. |
| Body limit · 413 | Narrow the request to the documented endpoint limit. Most combined writes have a 64 KiB outer cap, Studio 256 KiB, WAV 2,000,000 bytes and photo JSON 3,000,000 bytes. Existing inner routes can apply smaller limits. |
| Body timeout · 408 | The body did not arrive within the bounded read. Check the network and saved records before a deliberate retry. |
| Invalid saved resource fields | A stored field fails a schema/domain check, even if its hash is internally consistent. Keep a backup and inspect the record; do not edit hashes to bypass validation. |
| Connection refused | Start the server from the correct project folder and keep its terminal open. Confirm the host/port rather than creating a new database in a different folder. |

Every combined-server response includes `X-Nexus-Request-ID`, generated by the server. It is a troubleshooting correlation value, not a login token or proof of identity. Request logs omit query strings, headers and bodies. Send only a trace ID and safe error description when reporting a problem; do not paste contact details, tokens, farm notes or database files unnecessarily.

## Verification limits

Automated tests cover request rejection before mutation, valid legacy writes, page/export scope, stored-domain checks and pure JavaScript reference/locking/response-order helpers. Real-browser unsaved-change and asynchronous workflow acceptance remains separately tracked until it can be run. No account roles, cloud deployment or agricultural models are introduced by this reliability batch.
